# PawPair

## Original Project 
**PawPair** is a complete redesign of the original starter project **PawPal+** (Module 2), a Streamlit app that helps pet owners organize their pet care responsibilities. The original app allowed users to input their available time, add pets, and create care tasks with priority labels. It generated daily schedules organized by priority level in chronological order, with filtering options to view tasks by completion status.

## Title and Summary

**PawPair: AI-Powered Pet Adoption Matching System**

PawPair is a full-stack AI-powered pet adoption assistant that helps adopters find their ideal pet companion. Built with React, Vite, FastAPI, and OpenAI API, the system uses a deterministic matching algorithm with weighted scoring and generative AI using RAG to make personalized pet recommendations.

**How It Works:**
1. User completes a 9-question lifestyle quiz covering housing, activity level, experience, and pet preferences
2. Quiz responses are converted into an adopter profile and sent to the backend matching engine
3. The matching engine applies hard filters (species preference, housing compatibility, household members) and scores eligible pets using a deterministic weighted algorithm across four categories: age, activity level, experience requirement, and personality traits (25 points each, 100 total)
4. Top 5 or less matching pets are displayed with match scores, key details
5. For each match, users can expand a personalized AI explanation generated by a RAG system that retrieves the adopter's profile, pet details, matched traits, and compatibility score. The RAG system generates score-aware explanations: high matches receive encouraging but realistic feedback while low matches (≤50%) honestly assess potential challenges, preventing overselling and building trust.
6. Users can retake the quiz to explore different matches

## Architecture Overview

PawPair uses a three-layer architecture: React frontend collects quiz responses and displays results, FastAPI backend loads 14 pets from JSON data and runs the deterministic matching algorithm that applies hard filters then scores eligible pets using weighted categories, and RAG service generates personalized explanations grounded in real match data via OpenAI API. Data flows from user quiz → adopter profile → matching engine (filters & scores pets from JSON) → ranked pet matches → RAG explanations.

## Setup Instructions

**Prerequisites:**
- Python 3.11+, Node.js 16+, npm
- OpenAI API key (get one at https://platform.openai.com/api-keys)

**Backend Setup:**
1. `cd backend`
2. `python -m venv venv`
3. Activate virtual environment: `source venv/bin/activate` (Mac/Linux) or `venv\Scripts\activate` (Windows)
4. `pip install -r requirements.txt`
5. Create `.env` file: `cp .env.example .env`
6. Add your OpenAI API key to `.env`: `OPENAI_API_KEY=your_key_here`
7. `python -m uvicorn app.main:app --reload`
8. Backend runs on `http://localhost:8000`

**Frontend Setup:**
1. `cd frontend`
2. `npm install`
3. `npm run dev`
4. Frontend runs on `http://localhost:5173` (or port shown in terminal)
5. Open the frontend URL in your browser

**Both servers must be running simultaneously for the app to work.**

## Design Decisions

**1. Deterministic Matching Algorithm vs. Generative AI Alone**
- **Decision:** Built a rule-based matching engine instead of using only generative AI to recommend pets
- **Why:** Deterministic matching ensures reproducible, explainable results with clear logic; users can understand WHY a pet was recommended
- **Trade-off:** Less flexible than pure AI, but gains transparency and prevents hallucinations

**2. Hard Filters + Weighted Scoring (Two-Stage Approach)**
- **Decision:** Applied mandatory hard filters (species, housing, household) before scoring
- **Why:** Some compatibility factors are non-negotiable; soft scoring alone could recommend incompatible matches
- **Trade-off:** Some legitimate matches are excluded, but critical mismatches are prevented upfront

**3. Species as Hard Filter (Not a Scoring Category)**
- **Decision:** Made species preference a dealbreaker instead of a soft score
- **Why:** A user who prefers dogs doesn't want to see cats ranked 2nd; species is a fundamental preference
- **Trade-off:** Less flexibility, but clearer intent and fewer wasted recommendations

**4. Four Scoring Categories (Age, Activity, Experience, Traits)**
- **Decision:** Weighted each category equally at 25 points for a 100-point scale
- **Why:** Balanced approach—no single factor dominates; all four matter for compatibility
- **Trade-off:** Assumes all four factors matter equally but in reality, individual adopters may prioritize differently 

**5. RAG for Explanations (Generative AI)**
- **Decision:** Used OpenAI API to generate personalized explanations instead of hardcoded templates
- **Why:** Score-aware tone adjustment requires understanding context; RAG grounds explanations in actual match data
- **Trade-off:** API cost and latency per explanation, but significantly better user experience and trust

**6. Lazy-Loaded Explanations**
- **Decision:** Generate explanations only when user expands a card, not upfront for all matches
- **Why:** Saves API calls and improves initial results page performance
- **Trade-off:** Initial delay when expanding explanations, but better overall UX

**7. Curated Pet Dataset (14 Pets in JSON)**
- **Decision:** Use local JSON with 14 curated pets instead of connecting to a dynamic database
- **Why:** Simpler to demonstrate system, full control over data quality and matching consistency
- **Trade-off:** Limited scalability, but easier to validate logic and test reliability

## Testing Summary

**Unit Tests: 42/42 Passing ✅**
- **Pet Repository** (6 tests): JSON loading, schema validation, trait enums, unique IDs, lookups
- **Match Engine** (36 tests): Eligibility filtering, age/activity/experience/trait scoring, score calculation, ranking, edge cases

**Human Evaluation: 4/5 Passing ✅**
Test cases across match score ranges (38%, 50%, 75%, 88%, 100%):
- ✅ High matches (75%+): Appropriately enthusiastic and specific
- ✅ Perfect match (100%): Excellent balance of enthusiasm and realism
- ❌ Medium match (50%): Tone too discouraging, leans negative when it should be balanced
- ✅ Low match (38%): Appropriately cautious while remaining constructive

**What Worked:**
- Deterministic matching algorithm produces consistent, explainable results across all score ranges
- Hard filters correctly exclude ineligible pets; no false positives
- Scoring system is balanced—all four categories (25pts each) contribute meaningfully
- RAG system excels at high matches: grounds explanations in real data, appropriate enthusiasm
- Human evaluation confirms system is functional end-to-end

**What Didn't Work:**
- RAG explanations for medium-range matches (45-55%) tend toward negative/discouraging language
- Score-aware tone adjustment works well at extremes but needs refinement in the middle ranges

**What I Learned:**
- Deterministic algorithms + AI explanations is a powerful combination: transparency + personalization
- Score-aware tone generation is harder to validate automatically—unit tests passed but human evaluation revealed tone issues in medium-range matches (50%)
- Combining unit tests + human evaluation provides complete coverage: logic correctness + user-facing quality
